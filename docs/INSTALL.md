# GuitarProVST3 安装与使用

## 安装

1. 关闭 Guitar Pro。
2. 解压发布 ZIP。
3. 双击 `Install.cmd`，脚本会按 GuitarProMCP 的方式请求管理员权限。也可以在 PowerShell 中运行：

```powershell
./install.ps1 -Elevate -HostDirectory 'C:/Program Files/Arobas Music/Guitar Pro 8'
```

插件安装到 Guitar Pro 的 `Plugins/imageformats`，并写入文件归属收据。已有本安装器收据的版本可直接再次运行 `Install.cmd` 更新；只有收据哈希仍与 DLL 相符时，更新或卸载才会继续。

如果安装目录已有旧的 `guitarpro_vst3_autoload.dll` 但没有 GuitarProVST3 收据，双击 `Install.cmd` 会先备份旧文件再完成安装。PowerShell 中可显式启用同样的迁移：

```powershell
./install.ps1 -Elevate -MigrateExisting -HostDirectory 'C:/Program Files/Arobas Music/Guitar Pro 8'
```

迁移会先把旧文件备份到 `Plugins/guitarpro-vst3-backups`，再安装当前版本。

更新已有安装：

```powershell
./install.ps1 -Elevate -Action Update -HostDirectory 'C:/Program Files/Arobas Music/Guitar Pro 8'
```

卸载：

```powershell
./uninstall.ps1 -HostDirectory 'C:/Program Files/Arobas Music/Guitar Pro 8'
```

也可以双击 `Uninstall.cmd`。

## 使用

实时 hook 只在 `config/host_manifest.json` 对应的 Guitar Pro 8.1.1.17 / Windows x64 文件全部匹配时启用；其他版本保持旁路。

在音源区域点击 `VST3`。识别成功的插件进入可用列表；识别中、失败和超时的插件不显示为可操作条目。后台识别超过 10 秒会忽略当前任务并继续队列。原生 GUI 打开和首次勾选/取消勾选的生效阶段可在诊断数据目录的状态与日志中查看，详细说明见 [P10 实现记录](P10_IMPLEMENTATION.md)。

标题工具栏只保留一个“关于”入口；窗口显示版本、已验证宿主范围、许可证、第三方声明和诊断数据目录，并提供“打开配置”和“启动时启用插件”开关。关闭开关后，插件下次启动不会扫描、加载或接入音频；重新打开开关后重启 Guitar Pro 生效。

音轨 VST3 位于 GP 音轨侧栏的原生音源效果链后；全局 Master VST3 位于曲谱侧栏的母带后期处理后。不再预加载整个插件清单；有曲谱时只按已保存的启用配置准备所需音轨/全局实例。勾选项进入“正在使用”，从上到下决定处理顺序，可拖动或使用 `Alt+Up` / `Alt+Down` 排序。切换音轨只改变该轨链，全局链保持独立。

三种链的启动策略不同，配置中的启用意图不等同于运行时已开始处理：

| 范围 | 启动与恢复行为 |
|---|---|
| 音轨 | 保存插件列表、启用意图、顺序和参数；新进程或重新打开曲谱时保持运行时停用，需要显式重新勾选。界面按实际运行时显示勾选状态，不清除保存的意图。 |
| 全局 Master | 有活动曲谱且宿主接入就绪后，按保存的全局启用配置自动恢复；准备完成后才能处理。 |
| 输入 | 独立于曲谱读取保存的插件、监听模式和增益；保存为“低延迟监听”时自动请求恢复，设备验证、实例准备和排空完成后才显示已生效。保存为关闭时保持监听关闭，首次未配置也默认关闭。 |

停用立即旁路处理；仍存活的实例与参数可复用，warm-cache 有容量上限。音轨移除、关闭曲谱、缓存淘汰或退出插件时会按归属释放实例。首次启用按需创建，初始化失败会记录错误，不阻止其他插件操作。

关闭 GUI 或选择区后效果继续工作；勾选切换会先显示“请求中”，后台准备完成后生效，准备期间界面仍可操作。全局插件默认只处理曲谱播放总线，不会自动监听输入设备。双击插件名称打开 GUI，停用插件会关闭其 GUI。音轨增删、重排、保存/另存和关闭重开会保留对应链和参数。

### 独立输入低延迟监听

1. 在 Guitar Pro 中选择 ASIO 设备和输入通道。
2. 点击音源区域的“输入 VST3”，在独立窗口中勾选需要的输入效果器。
3. 打开“低延迟监听”，等待状态变为“低延迟监听已生效”。首次准备会创建实例并排空原生监听的旧输出，期间可能暂时听不到输入。
4. 用“监听增益”调整输入贡献。输入与 RSE 最终相加，需要留出音量余量；输入插件自身报告的延迟仍会增加实际监听延迟。

状态区显示实际原生监听旁通、输入通道、采样率、驱动/回调帧数、插件报告延迟和错误。未通过验证的格式显示未知；切流配置拒绝与插件处理错误分开统计。出现“混音削波”时降低监听增益。

已实测设备为 Studio 2 PRO / Midiplus USB Audio ASIO，实际采样率 192000 Hz、驱动及 callback 均 64 帧，GP 内部为 44100 Hz。当前只在匹配的 192000 Hz ASIO 流和已验证 SRC 拓扑上激活；Standard、其他采样率或无法核对的流会显示“当前设备或宿主暂不支持低延迟监听”。当前设备对 128～4096 帧的切换请求均拒绝并恢复 64 帧，不能据此认为这些 buffer 已实测支持。受限期间保留输入配置，回到受支持流后自动重新准备。

输入链的插件、顺序、参数、编辑器和监听增益独立于音轨/全局链。切谱、切轨和全局启停不会同步输入参数。低延迟开关与输入配置会保存，启动后仍需等待设备验证和实际激活状态；首次未配置时默认关闭。

“输入监听已静音”表示当前输入贡献没有输出：激活后清空输入链或遇到处理错误时会保留 GP/RSE 播放，并继续抑制已接管的原生监听贡献。检查输入插件/设备后重新启用；明确关闭“低延迟监听”会恢复原生监听路由，不会强制打开原来关闭的 Guitar Pro Line-In。未曾成功接管时的准备失败保留原路由。

该模式旁通的是原生监听对输出的贡献，原生输入 DSP 仍运行以维护宿主状态，不代表其 CPU 开销消失。Guitar Pro 8 官方用户手册明确不提供音频录制功能；此功能提供实时监听。验证细节见 [P13 实现记录](P13_IMPLEMENTATION.md)。

旧 `GPVST3_P4_ROUTE=input_insert` / `bus_mix` 保留为兼容和开发回归入口；它们不是新的低延迟模式。旧模式的全局参数镜像行为仅作用于旧输入实例。

## 数据目录

默认目录为 `%LOCALAPPDATA%/GuitarProVST3`：

- `effect-chain.json`：schema 2 的 global/track/input 链、参数和状态。顶层 `input` 保存输入插件、`monitor_mode` 和 `input_gain`，不归属某份曲谱。只持久化启用、已配置、带错误或带插件状态的数据；旧版本写入的空音轨和完整清单会在读取大文件时自动压缩。旧 schema 1 会自动迁移到 `global.effects`，请保留该文件。
- `settings.json`：插件启动开关。缺失或无效时默认启用。
- `vst3-catalog-cache.json`：自动生成的扫描缓存。缓存损坏会自动重建；需要手动重建时，关闭 GP 后只删除该文件并重新启动。

自动刷新不会反复识别已超时的同一插件；再次点击 `VST3`、插件文件更新或扫描器版本变化会触发重试。

开发构建和宿主回归见 [测试与验证](TESTING.md)。
