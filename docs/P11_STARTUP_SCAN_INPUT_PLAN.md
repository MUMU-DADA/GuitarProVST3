# P11：启动阻塞、扫描生命周期与吉他输入路由计划

状态：已实现（2026-09-12；宿主/ASIO 证据按环境记录）  
关联文档：[P10 ASIO、低延迟与输入链计划](P10_ASIO_LATENCY_INPUT_PLAN.md)、[P10 实现记录](P10_IMPLEMENTATION.md)

本轮针对三条实机反馈制定收敛计划：安装插件后启动/打开曲谱首屏长时间卡死；插件运行期间重复自动扫描列表；吉他输入仍绕过本插件 VST3 效果链。计划先建立可区分的时间线和路由证据，再修改调度与音频边界，最后用真实 Guitar Pro 宿主和 ASIO 设备验收。

## 问题与完成目标

| 编号 | 反馈 | 完成目标 | 必须提供的证据 |
| --- | --- | --- | --- |
| P11-1 | 先启动程序再打开曲谱时至少卡死约 10 秒；直接双击曲谱时程序无法正常打开 | 打开程序、打开曲谱和首帧 UI 不等待插件扫描、第三方 factory、processor/editor 创建或全量音轨恢复；曲谱文件可正常启动并进入可交互状态 | 冷/热启动时间线、UI 线程阻塞区间、曲谱打开结果、迟到任务计数 |
| P11-2 | 运行过程中疑似持续扫描插件列表 | 每次进程生命周期最多自动后台扫描一次；扫描完成后只允许用户手动刷新，或明确的插件目录变化事件触发一次失效并重新扫描 | 扫描请求/开始/结束/原因计数、目录快照哈希、重复请求被合并的日志 |
| P11-3 | 吉他输入不经过本插件 VST3 效果 | 明确 ASIO capture tap、输入链实例和最终监听/混音写回点；输入样本经确定性 VST3 处理后才能进入监听输出 | 真实 ASIO 回调中的处理计数、前后样本 hash/能量、buffer 地址与 sequence、录音或 loopback |

## 范围和边界

范围包括启动关键路径、VST3 catalog 生命周期、Qt/宿主观察器触发、ASIO capture 到监听输出的路由、输入链状态和诊断。暂不承诺绕过 Guitar Pro 私有音频层、兼容所有宿主版本或替所有 ASIO 驱动消除自身安全缓冲；无法确认 buffer 所有权时保持 observation-only，不保存借用指针。

现有 P10 夹具 PASS 只能证明可重复代码路径。`processInterleaved` 被调用、DLL 加载成功、菜单能枚举插件或返回 JSON，都不能单独证明 P11-1/P11-3 已完成。

## 分阶段计划

### P11.0：建立问题基线和观测开关

- 在 `startup_timeline` 增加进程启动、宿主初始化、曲谱请求、曲谱完成、首帧可见、首帧可交互、首次 callback、扫描开始/结束、输入处理和最终写回时间戳。
- 给每次扫描和输入处理附加 `request_id`、`reason`、线程名、状态和结果；音频线程只写原子计数/时间戳，汇总在控制线程完成。
- 增加诊断开关，允许在不改动第三方插件的情况下禁用扫描、禁用输入链、仅观测 capture tap，并记录开关实际生效范围。
- 固定至少两条启动路径：先启动再打开曲谱、直接打开曲谱文件；分别记录卡死时长、是否进入主界面、曲谱是否加载和进程退出方式。

验收：同一版本、同一曲谱和同一插件目录下，三条问题均能由结构化证据复现或明确标为“未复现”；禁止只用主观体感作为基线。

### P11.1：解除启动和曲谱打开阻塞

- 把插件目录枚举、缓存读取、主动识别、第三方 factory 加载、processor/editor 创建和全量音轨上下文发现从启动/曲谱打开关键路径移出；关键路径只恢复最小 UI 和已配置链的轻量状态。
- 统一使用可取消的后台任务；曲谱关闭、重新打开或宿主退出时取消未完成任务，迟到结果按 generation 丢弃，不得回写旧曲谱或旧音轨上下文。
- 禁止在 UI 线程同步等待 worker、等待插件锁、访问磁盘或调用第三方 module；所有跨线程结果通过一次性 queued update 合并提交。
- 对直接打开曲谱路径增加“先显示主界面、后异步恢复插件状态”的降级顺序；任何插件初始化失败只影响该链，不阻止曲谱打开。
- 在首帧可交互后再安排音轨上下文维护，设置明确的初始延迟和节流窗口，避免观察器在启动阶段反复触发重建。

目标门槛：安装插件但无启用链时，冷/热启动首帧可交互时间相对未安装基线增加不超过 `max(100 ms, 10%)`；UI 线程单次同步工作不超过 16 ms；直接打开曲谱成功进入可交互主界面。超时任务必须可观测并回退，不能继续阻塞。

### P11.2：把自动扫描收敛为一次性生命周期

- 在 `vst3_catalog` 增加明确状态机：`not_started → scanning → ready`，失败为带退避的 `failed`；同一 generation 只允许一个扫描 future。
- 启动时仅由单一 owner 发起一次后台扫描；其他模块只能读取快照或订阅完成事件，禁止各自调用 `beginAsync`、定时器重扫或在每次音轨/编辑器刷新时触发扫描。
- 扫描完成后缓存目录快照（路径、文件时间/大小或哈希）和 catalog generation；运行期间不主动轮询目录。用户点击“重新扫描”时显式递增 generation，取消旧任务后启动一次新扫描。
- 若必须响应安装/卸载事件，只接受明确的文件系统事件或用户动作，并做去抖与请求合并；相同快照不重建列表、不重新加载 module。
- UI 显示扫描状态、最后一次原因、完成时间和被合并的请求数；扫描失败保留上次可用快照并允许用户手动重试。

目标门槛：单次进程生命周期自动扫描计数为 1；无用户动作且无目录变化时扫描计数保持不变；连续点击或多个观察器请求最多产生一个实际扫描任务。日志能指出每次扫描的唯一原因。

### P11.3：锁定吉他输入到 VST3 的真实路由

- 在目标 Guitar Pro 版本确认 ASIO capture tap 的调用点、交错/平面格式、通道数、block size、buffer 所有权和有效期；确认前不得向宿主最终输出写回。
- 为输入建立独立 `input` scope 和固定实例生命周期，不依赖当前选中音轨；输入链的启用、旁路、顺序和 state 与 track/global 链分离。
- 在真实 callback 中严格执行 `capture → 格式/通道适配 → input VST3 → input_insert 或 bus_mix → 监听/最终输出`；任何容量、格式、processor 或 owner 不匹配都直通并增加原因计数。
- 使用确定性增益/加常数测试 VST3，对输入处理前后样本 hash、能量和 sequence 做断言；同时记录输入处理块、旁路块、错误块、写回地址和最后失败原因。
- 用真实吉他输入和 ASIO loopback 验证监听声音改变且关闭 input 链后恢复原生声音；切换曲谱、选中音轨和打开编辑器不得替换 input 实例。
- 若 Guitar Pro 只把 ASIO 输入送入自带效果器而未暴露可写回 tap，记录为宿主受限，保留 observation-only 证据并停止宣称“输入已经过 VST3”。

验收：真实 ASIO 回调中连续观察到 input processor 调用和当前回调 buffer 写回；确定性测试插件造成预期样本变化；输出监听/loopback 可复现该变化；关闭链后路径恢复且无静音扩大、越界或 deadline 连续超时。

### P11.4：回归和发布门槛

- 复跑 P8/P9/P10 构建、state、UI、runtime、ASIO 和输入路由专项；新增 `test-p11-startup.ps1`、`test-p11-scan-lifecycle.ps1`、`test-p11-input-route.ps1`，输出独立 evidence JSON。
- 启动矩阵覆盖：未安装插件、安装但旁路、安装且无配置链、启用确定性输入插件；路径覆盖先启动后开谱和直接双击曲谱。
- 设备矩阵至少覆盖一套 ASIO mono guitar input → stereo monitor 和另一种 block size；记录采样率、驱动版本、曲谱哈希、插件目录快照和环境开关。
- 提交前执行构建、专项脚本、`git diff --check`、`git status --short` 和敏感/产物检查；不把驱动配置、录音、测试 VST3、`.tools` 或 `artifacts` 打入发布包。

## 完成定义与风险

P11 只有在三项目标各自拥有真实宿主证据、可重复夹具和失败回退路径后才可标为完成。仅有代码审查、模拟 callback、菜单枚举、DLL 加载或 catalog JSON 不足以验收。第三方插件 factory 卡顿、Guitar Pro 私有 AudioLayer ABI、ASIO 驱动安全 buffer 和输入 tap 所有权仍可能构成宿主受限项；这类结果必须在实现记录中单独标注，并保留复现条件、诊断输出和下一步依赖。
